## Summary

Five semantic-search RPCs are built (`search_recipes_semantic`, `search_recipes_text`, `search_recipes_by_ingredients`, `find_similar_recipes`, `get_recipe_recommendations`) and matching `apiClient.rag*` wrappers exist — but only the chat surface uses them. `RecipeList.tsx` does naive `title.includes(query)` filtering. `recipe_reactions` and `dietary_tags` are write-only.

This MOP wires the existing RAG infrastructure into the Recipes page (search + similar-rail), promotes reactions and dietary tags to ranking signals for `get_recipe_recommendations`, and adds "Suggest meals for this week" to the planner.

Source: `docs/AI_INTEGRATION_AUDIT.md` Top 5 Product recommendations #1, #3, #5.

---

## Scope of Work

> Full scope pending. Initial draft consolidates audit findings — Phase split, file lists, and verification block to be added on planning pass.

### Phase 1: Recipes page RAG wiring
**Files affected:** `src/components/recipes/RecipeList.tsx`, `src/components/recipes/RecipeSearch.tsx`, `src/pages/Recipes.tsx`

Replace `title.includes()` filtering with `apiClient.ragSearch`. Wire the decorative filter chips (dietary, prep time, difficulty) to actual backend filters. Surface a `find_similar_recipes` rail on `RecipeDetail`.

### Phase 2: Reactions + tags as ranking signal
**Files affected:** Supabase RPC `get_recipe_recommendations` (new migration), `src/services/api.ts`

Feed `recipe_reactions` + `recipes.detected_allergens` + `recipes.dietary_tags` into `get_recipe_recommendations` scoring. Surface "Recommended for you" on home / planner.

### Phase 3: Meal planner suggestions
**Files affected:** `src/pages/MealPlanner.tsx`, new edge function `meal-suggestions/`

"Suggest a week of dinners" — single LLM call given (household preferences, recipe collection summary, reactions, days to fill) → slot assignments. Uses `get_recipe_recommendations` for scoring.
