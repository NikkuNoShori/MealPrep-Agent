## Summary

MOP-0009 Phase 4 introduces a `recipe-pipeline-tester` subagent that runs URL/text/video adapters against a fixture set and diffs against golden JSON. This MOP builds that fixture set — the corpus of known recipe inputs + expected outputs that the tester exercises.

Split from MOP-0009 because fixture authoring is its own bounded, growable effort. MOP-0009 ships the tester + a thin seed fixture; this MOP grows the library independently.

Source: AI Integration Audit (extraction is highest-variance code in repo, zero tests); MOP-0008 design (extraction reliability is unmeasured).

### Phase 2: URL adapter fixtures (P0)
**Target:** 10 fixtures covering:
- 3 major recipe sites with clean JSON-LD (NYT Cooking, Serious Eats, Bon Appétit)
- 2 recipe blogs with JSON-LD but extra noise (ads, sidebars, comments)
- 2 sites without JSON-LD (force LLM-only extraction)
- 1 multi-recipe roundup page
- 1 paywall / 403 page (expected: empty/error output)
- 1 non-recipe page (expected: error or "no recipe found")

Each fixture: HTML snapshot + golden JSON output + brief README note on what the fixture stresses.

### Phase 3: Text adapter fixtures (P0)
**Target:** 8 fixtures covering:
- Simple plain text recipe (1 recipe)
- Recipe pasted from a PDF (whitespace artifacts)
- Multi-recipe text dump (3+ recipes in one paste)
- Recipe in non-English with English ingredients
- Recipe with unit ambiguity ("1 cup OR 240ml")
- Recipe with fractional amounts (½, 1 1/2)
- Recipe with no quantities ("to taste")
- Garbage text (expected: schema validation failure → partial result with warnings)

### Phase 4: Video adapter fixtures (P1)
**Target:** 4 fixtures covering:
- High-quality OCR (clear cards, sequential frames)
- Low-quality OCR (motion blur, partial text)
- Multi-recipe video (creator shows variations)
- Video with NO text on screen (expected: graceful empty output)

Video fixtures are JSON arrays of frame URLs (publicly accessible test images), not video files.

### Phase 5: Fixture-tester integration
**Files affected:** `supabase/functions/recipe-pipeline/__tests__/adapter-fixtures.test.ts` (new)

Deno test harness that:
1. Iterates all fixtures
2. Calls the relevant adapter with the input
3. Diffs the output against the golden JSON
4. Reports pass/fail per fixture with structured divergence

Golden updates require explicit human approval — the `recipe-pipeline-tester` subagent (MOP-0009 Phase 4) gates this.

## Notes

- **Fixtures are dev-only.** They never ship in the runtime bundle. The `__fixtures__/` directory is excluded from edge function deployment.
- **HTML snapshots, not live URLs.** The URL fixtures must use cached HTML to avoid flaky tests when source sites change. Refresh snapshots manually when intentional (and update goldens accordingly).
- **Golden updates require human approval.** The test harness MUST refuse to "auto-fix" goldens. If a fixture starts failing, the developer investigates whether the adapter regressed or the source site changed — only then do they update the golden.
- **Fixture growth is the long-term value.** Every production extraction bug should result in a new fixture being added. Over time the library becomes the institutional memory of "things that broke once and shouldn't break again."
- **Cost control.** Vision fixtures (video adapter) hit the OpenRouter API per run. Keep the fixture set small and intentional; not every video case needs a fixture.
